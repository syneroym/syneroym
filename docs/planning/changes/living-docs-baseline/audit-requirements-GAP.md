# Audit: requirements spec, batch GAP

Reader: a developer who will fix [docs/system-requirements-spec.md](../../../system-requirements-spec.md) and [docs/planning/traceability-matrix.md](../../traceability-matrix.md).

This audit checks Batch GAP of the requirements specification against the code. It identifies major capabilities, mechanisms, and architectural contracts that exist in code and tests but have no requirement (or only an inaccurate or obsolete passing mention) in `docs/system-requirements-spec.md`. It changes no code and does not edit the spec. It is part of the [living docs baseline](change.md). All checks are static reading of the code, tests, configuration, and ADRs. Paths are relative to the repository root.

Areas covered:
- 2.1 Node Administration & Ownership (Substrate claim, `ControllerAgreement`, KEK injection, key separation)
- 2.2 Client Gateway & Session Identity (Gateway identity modes, Node Auth Service, challenge-response login, session tokens, WebRTC blind tunnel fallback)
- 2.3 Application Topology, Discovery & Dynamic Bindings (Two-tier logical discovery, signed `TopologyDocument`, `AppScope`, labeled gateway subdomains, static inventory push with epoch compare, three-valued service visibility, master anchor revocation tombstones)
- 2.4 Asynchronous Reliability & Message Plumbing (Durable outbox, DLQ with operator replay CLI, call deduplication fences, single-select component shutdown race, MQTT topic namespace tenancy)
- 2.5 Security, Cryptography & Data Custody (Signed record envelope with host-only signing, stream encryption query mode, local-only RPC admission firewall, encrypted identity backup archive, bilateral agreement receipts)
- 2.6 Application Lifecycle, Packaging & Native Runtime (Dual-build SynApps, zero-runtime static asset blob passthrough, lifecycle hooks `init`/`migrate` without filesystem snapshots)
- 2.7 Observability & Operator Diagnostics (Control-plane alert engine `AlertStore`, diagnostic health probes and CLI)

Verdicts follow the audit instructions: IMPLEMENTED, PARTIAL, NOT BUILT, DIVERGES, STALE, UNCLEAR, N/A. Only code and tests count as proof.

### Main findings

1. **Node ownership and administration boundaries are absent from the requirements spec.** The codebase strictly requires an offline substrate claim step (`roymctl substrate claim`) producing a mutually signed `ControllerAgreement` before granting `substrate/admin` capabilities over the wire. Unowned substrates fail closed to prevent unauthorized remote deployment. The spec does not mention this ownership model, the claim command, or the `ControllerAgreement` structure.
2. **Client gateway and browser session authentication are implemented but missing from requirements.** The client gateway supports three explicit identity modes (`Open`, `Login`, `Fixed`), a challenge-response Node Auth Service issuing signed bearer tokens and setting `syneroym_session` cookies, and a WebRTC WebSocket blind tunnel (`/__syneroym/tunnel`) for browser fallback. The spec only refers to lightweight consumer keys in passing, omitting gateway modes, auth services, and tunnel proxies entirely.
3. **The two-tier logical discovery overlay and signed topology documents are not specified.** The system resolves services using Tier 1 (registry/DHT master anchor lookup) and Tier 2 (fetching a canonical `TopologyDocument` signed by the app-instance master key from the App Supervisor). It also uses labeled subdomains (`-a...-s...`) to route HTTP traffic. The spec describes flat registry and bootstrap lookups and contains no requirement for topology documents or labeled host headers.
4. **Asynchronous reliability plumbing (outbox, DLQ replay, dedup fences, and MQTT tenancy) is implemented with precise contracts unrepresented in the spec.** The substrate provides owner-local SQLite outboxes with exponential backoff, dead letter queues with CLI inspection and replay (`roymctl supervisor outbox/dead-letters/replay`), router-level deduplication fences via `async.db`, and tenant-isolated MQTT topics (`svc/<service_id>/`). The spec describes offline queues and MQTT only at an abstract level.
5. **Host-guest security boundaries are strongly enforced in code but omitted or contradicted in the spec.** The codebase uses a canonical JSON signed record envelope (`ENVELOPE_VERSION = 1`) with host-only signing via `syneroym:signing` (guest components cannot sign or touch private keys), a local-only RPC firewall (`NOT_LOCAL = -32013`) protecting private Roym services, and bilateral agreement receipts (`AgreedTerms`). The spec erroneously claims signed record formats are deferred and lacks requirements for host-only signing isolation or RPC admission firewalls.
6. **Application upgrade safety in code diverges from the spec's snapshot claims.** Section 3 of the spec asserts that the substrate takes automatic filesystem snapshots of SQLite databases before upgrades and rolls back automatically on failure. In code, the substrate invokes guest lifecycle hooks (`init` vs `migrate`), but automatic snapshots and rollbacks are deferred.
7. **Dual-build execution and static asset blob streaming are absent from application lifecycle requirements.** SynApps compile either as sandboxed WASM components or directly as native binaries (`syneroym-app-host-native`) with verified behavioral parity. The substrate also serves static web assets directly from the blob store without instantiating the WASM runtime. The spec mentions only WASM and container sandboxes.

## 4. Gaps noticed

1. **Node Administration & Physical Ownership**: The requirements spec describes access control via UCAN capabilities, but omits the fundamental transition from an unowned substrate to an owned substrate via `ControllerAgreement` and `roymctl substrate claim`.
2. **Web Client Ingress & Session Infrastructure**: The client gateway proxy, its three identity modes (`Open`, `Login`, `Fixed`), the Node Auth Service challenge-response handshake, `syneroym_session` cookie verification, and the WebRTC blind tunnel fallback (`/__syneroym/tunnel`) are missing from the spec.
3. **Application Topology & Multi-Node Orchestration**: The two-tier logical discovery architecture, signed `TopologyDocument` structures, `AppScope::{Local, Foreign}` domain separation, labeled gateway subdomains (`-a...-s...`), and monotonic binding epochs are implemented across the substrate and supervisor but absent from requirements.
4. **Asynchronous Reliability Infrastructure**: Detailed contracts for durable work outboxes, Dead Letter Queue (DLQ) inspection and replay CLIs, receiver-side deduplication fences (`async.db`), and single-select component shutdown races are completely omitted from the spec.
5. **Application-Tier Security Boundaries & Portability Formats**: The canonical signed record envelope (`ENVELOPE_VERSION = 1`) with host-only signing (`syneroym:signing`), the local-only RPC admission firewall (`NOT_LOCAL = -32013`), bilateral agreement receipts (`AgreedTerms`), encrypted identity backup archives (`IDENTITY_BACKUP_VERSION = 1`), and sealed restore bundles are fully functional in code but lack spec requirements.
6. **Dual-Build Architecture & Static Asset Serving**: Native host compilation alongside WASM, and zero-runtime static asset blob streaming without component instantiation, are omitted from application lifecycle requirements.
7. **Operational Diagnostics & Health Sweeping**: The control-plane alert engine (`AlertStore`, `AlertKind`), read-only health diagnostic probes (`StatusQuery`), and operator CLI monitoring commands (`roymctl app health/alerts`) exist in code but have no requirements in the specification.
