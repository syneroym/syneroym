# Audit: architecture doc, "Connectivity Substrate In Heteregenous networks" (batch F)

Reader: a developer who will split and fix [system-architecture.md](../../../system-architecture.md).

This is a light audit of doc lines 1373-1836. It changes no code and does not edit the doc. Part of the [living docs baseline](change.md).

**How I audited.** Each subsection gets a status (implemented, partly implemented, or Envisioned). I checked claim by claim only where the text gives specifics: DID syntax, record keys and fields, attachment prefixes, the transport interface, the HELLO handshake, protocol names, the 1000-byte limit. A subsection that is a general design gets one summary row. Only code and tests count as proof. All checks are static reading. Paths are from the repository root.

**Verdicts.** MATCHES (the code does this), DIVERGES (the code does something else; the code is right), NOT BUILT (nothing in the code does this), STALE (renamed or removed), UNCLEAR (I could not decide).

**Key fact for the whole section.** The section has no "Envisioned" marker anywhere, so every statement reads as working. In fact the section describes a design that is only partly built. What is built is: DHT and registry discovery, Iroh transport (direct, hole punch, relay), and a route preamble that declares the protocol. What is not built: attachment-type records, gateways (BLE/LoRa), path ranking, a transport adapter interface, the HELLO handshake and the wRPC adapter.

Overlap with audited sections: Layer 1 (IDs `L1-xx`, `MH-xx`, `BD-xx` in [audit-architecture-A.md](audit-architecture-A.md)) and Layer 3 Identity (IDs `B-I-xx`, duplicate D4 in [audit-architecture-B.md](audit-architecture-B.md)). I reference those IDs and do not re-audit them. The change spec [roym-integrated-experience-spec.md](../../../roym-integrated-experience-spec.md) does not touch this section.

Main findings:

1. **Identity syntax is wrong.** The doc uses `did:p2p:nodeA` and `did:p2p:svc123`. Code has no `did:p2p`. All DIDs are `did:key:h<z32>` (`crates/identity/src/substrate.rs:142-146`).
2. **The DHT record format in the doc is not the code's.** The doc has a service record (`service_did`, `node`, `protocols`, `seq`) and a node record with `q:`/`i:`/`g:` attachments. Code has one `EndpointInfo` (`service_id`, `substrate_id`, `endpoint_type`, `mechanisms`, `nickname`, `is_private`, `ttl`, `not_after`, `generation`). Its mechanisms are `Iroh` and `WebRtc` only. There is no `protocols` field. The DHT key is the signer's public key, not `hash(did)`.
3. **Connection establishment does not fall back.** The doc says "for path in paths ... if success: break". The SDK returns the error of the first failed Iroh dial and never tries the next mechanism (`crates/sdk/src/client.rs:390-392`). WebRTC mechanisms are skipped (`client.rs:403-405`). This is a bug-shaped gap, not only a doc gap.
4. **Gateways, BLE, LoRa, path ranking, HELLO negotiation and the JSON-RPC to wRPC adapter are NOT BUILT.** Only config types for BLE/LoRa and a `transport_bridge` role exist, and nothing reads them. The adapter that is built is JSON-RPC to a WASM guest call.
5. **The doc's own anchor is broken.** The heading is spelled "Heteregenous". Links at doc lines 29 and 145 point to `#connectivity-substrate-in-heterogeneous-networks` (already `L1-02` in batch A).

## 4. Gaps noticed

1. **App-supervisor logical resolution.** Logical service names resolve through the app supervisor, above the router (`crates/app_supervisor/src/service/resolve.rs:18`). This section has no step for it (`B-I-24`).
2. **WebRTC as a first-class mechanism.** `EndpointMechanism::WebRtc` is in the record format, but this section never mentions WebRTC (`crates/core/src/dht_registry/types.rs:55-66`). The SDK dial loop ignores it (`crates/sdk/src/client.rs:403-405`).
3. **Registry before DHT.** The built discovery is an HTTP community registry first and a DHT fallback, with a write-back of DHT hits (`crates/core/src/dht_registry/client.rs:195-270`). The section describes only the DHT.
4. **Record freshness and replacement.** `not_after` (30 days), republish every hour, and last-writer-wins by pkarr timestamp (`types.rs:16-37`). Not described here.
5. **Private services.** `is_private` records are not sent to the DHT (`crates/core/src/dht_registry/client.rs:146-151`), and a client reaches such a service through its host's record (`crates/sdk/src/client.rs:74,253`).
6. **Route preamble options.** `enc=ecdh-p256`, `delegation`, `dir` (`crates/router/src/preamble.rs:25-35`). The connection handling text has no encryption or identity step.
7. **Client-side connect timeout.** The SDK has `DEFAULT_CONNECT_TIMEOUT` of 10 seconds (`crates/sdk/src/client.rs:33`). Not described.
8. **Unused config for BLE/LoRa and `transport_bridge`.** Parsed but never read (`crates/core/src/config/base.rs:195-205`, `roles.rs:340-350`). They look like working options in the sample config. Add to `docs/planning/deferred-backlog.md` as an open item (or remove the sample lines).
