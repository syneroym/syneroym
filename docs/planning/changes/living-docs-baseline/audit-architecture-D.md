# Audit: architecture doc, batch D (Observability, Security, Resolved TBD Items)

Reader: a developer who will fix [system-architecture.md](../../../system-architecture.md).

This audit checks three headings of the architecture doc against the code:
"Observability Architecture", "Security Architecture" and "Resolved Architecture
TBD Items". It changes no code and does not edit the doc. Part of the
[living docs baseline](change.md).

**How to read the verdicts.** Only code and tests count as proof. Paths are from
the repository root. Every MATCHES row has a `file:line` citation. The doc's
status model has two values: no marker means implemented, "Envisioned" means
not built. The verdicts below are audit findings, not doc status values.

- **MATCHES**: the code does this.
- **DIVERGES**: the code does something different. The code is right, so the doc needs a fix.
- **NOT BUILT**: nothing in the code does this. "Presented as" says whether the doc writes it as working or as planned.
- **STALE**: the name no longer exists. The current name is given.
- **UNCLEAR**: I could not decide. The row says what I looked at.

All checks are static reading. I did not run the substrate or the tests.

Ports in this report come from `crates/substrate/config.dev.toml:176-195` and
`crates/substrate/src/main.rs:215-224`. The health endpoint is on 7966 and the
metrics endpoint on 7967. Neither is port 8080.

Main findings:

1. **The provider-facing half of "Observability Architecture" does not exist.** There is no `health-narrator`, no `/admin` page, no `HealthState`, no diagnostic bundle, no ring buffer, no notification dispatcher and no `syneroym observability enable`. Only the "Simulation Testing" subsection carries the Envisioned marker. Everything else reads as working.
2. **What the code really has is small.** Logs go through `tracing` (events only, no spans). Metrics go through the `metrics` facade into an in-memory `MemoryRecorder`. `/health` answers plain `OK` on port 7966. `/metrics` answers a JSON snapshot (not Prometheus format) on port 7967. OTLP config types exist but nothing reads them.
3. **"Substrate Integrity & Remote Attestation" is entirely NOT BUILT** and has no Envisioned marker. The requirements spec calls attestation optional.
4. **Three crypto names in the encryption diagram are stale or wrong.** 1-to-1 chat uses `vodozemac`, not `libsignal-protocol-rust`. Group chat uses an owner-distributed AES-256-GCM key, not MLS (ADR-0013 Amendment 1). The "DERP relay AES-256-GCM envelope" is an opt-in per-stream option (`?enc=ecdh-p256`), not a relay feature.
5. **The Isolation diagram has an edge the code does not allow.** "APP1 <-> APP3 direct access after substrate-vetted initialization" has no code. The diagram also shows one SQLite per SynApp, but the code has one per service.
6. **The "Resolved Architecture TBD Items" intro is STALE** (the requirements spec has no `[TBD]` markers). Rows 1-4 match the code. Rows 5-17 repeat Trust, Payments, Discovery and Bootstrap statements that are mostly not built, and none carry the Envisioned marker.

## 4. Gaps noticed

1. **Supervisor health sweep and alerts.** The real health feature is `StatusQuery` plus `AlertStore` with `AlertKind` (`SubstrateUnreachable`, `InstanceNotRunning`, `ProbeFailing`, certificate near expiry or expired): `crates/sdk/src/health.rs:1-25`, `crates/app_orchestration/src/alerts.rs:1-45`. The Observability section does not mention it.
2. **Real metric names and the 1-second system sampler** (`substrate.request.*`, `substrate.proxy.*`, `substrate.wasm.*`, `substrate.fdae.*`, `substrate.system.*`, `substrate.tokio.active_tasks`): `crates/observability/src/metrics.rs:29-50`.
3. **Observability config.** `[roles.observability]` has `health`, `metrics` and `tracing` sub-tables, each with bind address and path; dev mode turns health and metrics on (`crates/substrate/src/main.rs:213-224`; `crates/core/src/config/roles.rs:456-515`). The doc names none of it. `tracing.otlp` is config-only.
4. **Unbounded memory in `MemoryRecorder`.** Every histogram sample is pushed into a `Vec` that is never trimmed (`crates/observability/src/recorder.rs:65-70`). A long-running node grows without limit. This is a risk, not only a doc issue. It may belong in the backlog.
5. **How isolation is really enforced for WASM.** Pooling allocator and memory cap, fuel and epoch time limits, empty `WasiCtx`, a node-interface denial (`orchestrator`, `security`) and a same-service gate on native capabilities: `crates/sandbox_wasm/src/engine/init.rs:335`, `host_capabilities.rs:429-433`, `crates/router/src/proxy/router.rs:138-195`, `crates/core/src/local_registry.rs:42-59`. The Isolation section shows none of these.
6. **Data-at-rest key chain is missing from the diagram.** SQLCipher database, per-service DEK, node KEK injected by `roymctl kek inject`, per-instance HKDF-derived KEK, vault table, and the Roym archive's recovery key: `crates/data_keystore/src/key_store.rs`, `crates/data_db/src/sqlite/service_store.rs:173-215`, `crates/identity/src/backup.rs`.
7. **Identity and admission layers are not in "Security Architecture".** Delegation certificates checked at stream open (`crates/router/src/handshake.rs:1-60`), UCAN capabilities, session cookies from the auth service, and `substrate/admin`-gated native verbs (`crates/control_plane/src/service/dispatch.rs:59-80`). The section covers encryption and isolation only.
8. **The `?enc=ecdh-p256` stream layer has no client.** The router implements it, but I found no SDK or gateway code that requests it (SEC-02). The doc should say who can use it, or the layer is dead code.

- **Claims:** 94 (Observability 46, Security 30, Resolved TBD Items 18).
