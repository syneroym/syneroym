Reader: a developer who will fix [system-architecture.md](../../../system-architecture.md).

This audit checks the end of the architecture doc against the code. It changes no code and does not edit the doc. It is part of the [living docs baseline](change.md). Format follows [audit-architecture-layer2.md](audit-architecture-layer2.md).

**Scope (doc line hints).** Addendum "Phase 3: Substrate & Application Lifecycle" (2159-2202), "Phase 4: Advanced Services & Tooling" (2204-2267), "Phase 5: Peer-to-Peer Community Primitives" (2269-2284), "Phase 6: High-Level Applications (SynApps)" items 0-7 (2286-2336), "Phase 7: Edge Expansion" (2338-2351), "Open Questions & Recommendations" (2353-2366), "Glossary" (2370-2390).

**Method.** Only code and tests count as proof. All checks are static reading. Paths are from the repository root. Every MATCHES row has a `file:line` citation.

**Presentation of the unbuilt items.** The doc's status legend (line 3) says every unbuilt item must carry the Envisioned marker. Nothing in this batch carries it. The addendum has one global note (line 1848, dated 2026-07-12) that says the text "describes target implementation". So each NOT BUILT row below is presented as a design or plan, in present tense, with no per-item marker. The one exception: Phase 7 and Phase 6 items 1, 4-7 read as plans in their wording, but they have no marker either. Disposition for all NOT BUILT rows is "keep as Envisioned" unless the row says otherwise.

Main findings:

1. **None of Phase 4 (observability pipeline, AI), Phase 5 (tag routing, satisfaction signals) or Phase 7 (mobile) exists in the code.** There is no `metrics.db`, no MPSC pipeline, no `rig-core`, no `sqlite-vec`, no tag forwarding, no EMA reputation, no push wake-up and no secure-enclave interface. A grep for these names finds nothing in `crates/`, `apps/`, `Cargo.toml` or `mise.toml`.
2. **Phase 3 is mostly right, with five precise errors.** The App Supervisor, the push of bindings and the `init()`/`migrate()` hooks are built. But: (a) `[LFC-MGT]` says the supervisor has "no service-facing directory interface", yet the `supervisor` WIT interface has a `resolve` verb that serves signed topology documents; (b) WebRTC is not a deploy transport (`crates/sdk/src/client.rs:404-406`); (c) the migration safety net (pause, snapshot, rollback) does not exist; (d) the doc says `execute_sql`, the WIT function is `execute-ddl`; (e) the protocol-profile handshake does not exist.
3. **Phase 6 describes a different product from the built Roym Hub.** The Hub is a web UI served by the `web` service and talks `POST /rpc` over HTTP, not a Tauri or WebView shell with a WebSocket or gRPC link. Cards are seven fixed signed record types with fixed client templates, not JSON layouts with an `actions` array. Payments, escrow, stamps, fuel quotas and portable envelopes are not built. Roym records what each side says about a payment and nothing more.
4. **Glossary: 9 of 17 terms are stale, unbuilt or wrong.** `SYN-SVC`, `SYN-MOD`, `HOME_RELAY`, `Space`, `CRDT`, `DERP` and `MLS` name things the code does not have. `wRPC` is reserved but not built. `LWW` says "per field", the code is per whole document.
5. **The doc's own rules are broken here.** Unbuilt items carry no Envisioned marker. The text uses the retired word "controller" for the supervisor. It contains a milestone ID ("M7"), a dated status note, and an undefined term ("DLN").
