### Main findings

1. **The Substrate Feature Coverage Matrix is largely speculative, referencing three non-existent applications (`Marketplace`, `Ledger`, and standalone `Chat`).** In reality, the single integrated product built in this repository is **Roym** (`crates/roym_core/app/roym.toml`, shipped in M06C, traceability matrix row 56). Roym exercises the Home Services Guild reference vertical across directory search (`roym_directory`), catalog listings (`roym_catalog`), profile management (`roym_profile`), quote/invoice negotiation (`roym_transaction`), encrypted conversation (`roym_conversation`), and the web UI (`roym_web/ui`). Neither a standalone `Marketplace` nor a `Ledger` application exists in the codebase (Owner Decision Q-A2; Overlaps O21).
2. **The matrix asserts that Chat exercises Pub/Sub, but in code Chat deliberately diverges from the Pub/Sub broker.** Row 1 claims `[PLT-DAT] Pub/Sub` is exercised by `Chat` for real-time delivery and typing presence. In architecture and code (ADR-0013 §6; `crates/wit_interfaces/wit/conversation/conversation.wit:1-3`), durable conversation is strictly decoupled from the MQTT broker (`syneroym:messaging`) because pub/sub brokers lack end-to-end encryption and causal order guarantees. Conversation messaging is provided by `syneroym:conversation` (`crates/conversation`), and typing presence is completely unbuilt.
3. **The matrix preserves obsolete conceptual terminology ("Space Managers").** Row 14 asserts that `[FND-IDT/IAM]` enforces "role-based access for Space Managers." As identified in earlier audits (Overlaps O24; Glossary GLS-14; batch R4), `SPACE-MGR` is an obsolete entity from the initial conceptual model that was superseded by Substrate Operators claimed via `ControllerAgreement` (`crates/identity/src/substrate.rs:48`), App Supervisors (`crates/app_supervisor`), and FDAE ReBAC policies (`crates/fdae`).
4. **All Later-Phase Additions (Accessibility, IoT non-IP mesh, Escrow, and Mutual Credit) are Envisioned, with Accessibility blocking M6 closure.** Base substrate flows and the Roym Hub web client have no ARIA attributes, keyboard navigation audits, or WCAG compliance passes, which traceability matrix row 10 (`[PRD-CUX]`) flags as blocking M6 milestone closure. Non-IP mesh integration (Zigbee/Thread/BLE), escrow multi-sig custody, and native mutual credit / system coins are unbuilt and correctly tracked in `docs/planning/deferred-backlog.md`. Localisation is partial: `ProfilePayload` includes an optional `locale: Option<String>` field, but the UI copy is hardcoded English.
5. **Heavy platform capabilities (AI, TPM 2.0 hardware security, credit network sharding, dynamic node leasing, and iOS push waking) remain completely unbuilt.** Nine of the nineteen matrix rows describe capabilities that are entirely unbuilt across both the substrate core and the application suite: AI participants with memory, hardware-backed multi-party signing, stateful settlement migrations, dynamic node leasing for flash sales, resource utilization billing for storefronts, automated version update rollback, and mobile OS background push wakeups.
6. **Citations to uncommitted ideas documents persist in the spec.** Line 1296 links to `https://github.com/syneroym/foundation/blob/main/ideas/commitment-network.md`, directly violating the repository guideline in `GEMINI.md` that living docs must never cite uncommitted documents in `docs/ideas/`.

## 4. Gaps noticed

1. **The Roym integrated product suite as the primary validation harness.** The coverage matrix lists `Chat`, `Marketplace`, `Ledger`, `Aggregator App`, `Hub / Admin`, `roymctl`, `Node Admin`, and `Mobile Hub`. In reality, the primary app exercising substrate capabilities is **Roym** (`crates/roym_core/app/roym.toml`, M06C, traceability matrix row 56), which exercises encrypted SQLite, blob storage, UCAN/FDAE access control, outbox async queueing, typed WIT RPC, dual-build native linking, signed record verification, client directory search merging, and the browser Hub web application.
2. **`syneroym:conversation` capability vs. pub/sub messaging.** The matrix lists pub/sub as the mechanism for chat (Row 1). It omits the built `syneroym:conversation` capability (`crates/wit_interfaces/wit/conversation/conversation.wit`, `crates/conversation/`), which provides double-ratchet end-to-end encryption (`vodozemac`), cryptographic DAG causal ordering, and member sync upon reconnection, deliberately avoiding the pub/sub broker per ADR-0013 §6.
3. **Signed Receipts and SynOrg credentials as trust evidence vs. public peer reputation scores.** The matrix lists `[P2P-REP]` for Marketplace (Row 17). It omits the built trust mechanism: Roym implements portable, verifiable signed credentials (SynOrg membership, moderation decisions, revocations) and bilateral `InteractionReceipt` records (`crates/roym_core/src/transaction.rs:136-150`), with client-side verification rather than a public peer reputation score or global rating engine.
4. **Client-side directory fan-out and deterministic merge vs. mesh matching fabric.** The matrix lists `[P2P-DSC]` for Aggregator App (Row 16). It omits the built directory mechanism: rather than a rendezvous-hashed leaf shard mesh fabric, the client queries multiple directory SynOrg endpoints directly and executes client-side deterministic round-robin merging with source and recency provenance (`crates/roym_directory/src/app/client_merge.rs`).
5. **Session tokens and Node Auth Service behind Client Gateway (ADR-0024, `crates/client_gateway`).** The matrix describes "Hub / Admin" identity and access (Row 14). It omits the built gateway auth architecture: the browser Hub logs into the local substrate node auth service, receiving a short-lived bearer session token, and client gateway verifies session tokens on `POST /rpc` pass-through routes.
6. **Outbox and Dead Letter Queue with operator replay surface (ADR-0023, `crates/async_queue`, `crates/app_supervisor/src/service/outbox.rs`).** The matrix cites offline outbox queuing for Chat (Row 4). It omits the substrate-level durable outbox, Dead Letter Queue (DLQ), and operator replay surface (`roymctl supervisor replay`, `dead-letters`) that guarantees at-least-once delivery of inter-service RPC and dependency binding updates across network interruptions.
