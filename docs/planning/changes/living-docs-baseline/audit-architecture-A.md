Reader: a developer who will fix [system-architecture.md](../../../system-architecture.md).

This audit checks four parts of the architecture doc against the code. It changes no code and does not edit the doc. It is part of the [living docs baseline](change.md). All checks are static reading. I did not run the substrate or the tests.

Main findings:

1. **Layer 1 describes a Bootstrap Server that does not exist.** No code assigns a home relay, keeps a relay list, mirrors relays to the DHT under `syneroym-relays.<version>`, or caches a relay list for 24 hours. A substrate gets its relay from a fixed config URL (`parent_coordinator.iroh.url`). Discovery is the community registry plus per-node pkarr records. The `*.syneroym.net` relay hostnames, the Local DNS cache, the community governance key and the TURN server do not exist either. Browser fallback is STUN plus a WebSocket "blind tunnel", not TURN.
2. **The Multi-Hop section is wrong about where the code lives and how it is reached.** The Layer 7 forwarding (`relay_to_next_hop`) is in `crates/router`, runs in every node (substrates too), and has no `hop-relay` name. A normal substrate publishes its own Iroh address, so callers dial it directly. A coordinator becomes the entry point only when a record names it. The doc's "cannot read them" claim holds only when the preamble asks for `enc=ecdh-p256`. The Rust client never does.
3. **The Entity Model and System Layers diagram mix the substrate with the Roym product.** Provider, Consumer and Aggregator are Roym transaction roles or product terms, not substrate entities. Reputation, Payments and the Aggregator have no substrate code. `SYN-MOD` is not a code term. A SynApp can span substrates, and one substrate has one configured relay, not many.
4. **Android phone (Tier 1) is not built.** The release workflow builds Linux x86_64 and aarch64, Windows and macOS only.

## 4. Gaps noticed

1. **Browser fallback path.** The WebRTC coordinator serves a bootstrap page, a service worker and `peer-proxy.js`, and runs a WebSocket "blind tunnel" that pipes the browser to an Iroh node (`crates/coordinator_webrtc/src/bootstrap.rs:115-118`, `bootstrap/tunnel.rs:9-44`). Layer 1 does not describe it.
2. **Coordinator `/v1/info` endpoint.** It reports status, connection cap, TLS expiry and relay state (`crates/coordinator_iroh/src/info_endpoint.rs:104-129`). The relay has an access list and a connection cap (`config.rs:82-99`, `route_handler.rs` `max_connections`). Relay TLS is configured separately from the info endpoint's TLS (`coordinator.rs:92-95`).
3. **Community registry as the built discovery piece.** HTTP `/register`, `/lookup`, aliases, master anchors, parent registry (`crates/community_registry/src/registry.rs`), plus the 1 h republish, 2 h registry TTL and 30-day `not_after` (`crates/core/src/dht_registry/types.rs:16-37`). Layer 1 never mentions these.
4. **How a substrate picks its relay.** Fixed config: `parent_coordinator.iroh.url`, `.webrtc.signaling_url`, `.webrtc.stun_servers` (`crates/core/src/config/base.rs:148-199`). `coordinator_discovery_url` is declared and unused (`base.rs:223`).
5. **Config flags that do nothing.** `enable_signalling` (Iroh and WebRTC) and the WebRTC `enable_relay` are parsed but never read to gate behavior (`crates/core/src/config/roles.rs:282,319-320`; only set in `crates/substrate/src/main.rs:137-149`). `transport_bridge`, `ble` and `lora` config are also unused (`roles.rs:257,341`).
6. **Third-party fallback.** With no relay URL, an Iroh endpoint uses the `N0` preset: n0's public relays and DNS discovery (`crates/router/src/net_iroh.rs:99-108`). The doc says nothing about this default.
7. **Coordinator mode of the router.** `RouteHandler::new_coordinator` runs with a mock registry, no sandbox and its own embedded MQTT broker (`crates/router/src/route_handler.rs:440-486`). A reader cannot learn this from the Layer 1 text.
8. **Client mechanisms.** The registry record type has a `WebRtc` mechanism, but `SyneroymClient` skips it ("Not implemented", `crates/sdk/src/client.rs:405`). Only Iroh is dialed by the Rust client.
