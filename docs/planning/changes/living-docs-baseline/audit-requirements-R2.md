### Main findings

1. **The Ecosystem diagram depicts an Aggregator hosting and managing services for providers, which diverges from the architecture and code.** In the diagram (lines 246–247), the Aggregator has edges `hosts for Provider` and `manages SynApp`. In the codebase and architecture decisions (Owner Decision Q-A4, `audit-architecture-overlaps.md` O22), an Aggregator is not a hosting provider. It is a directory-type SynOrg service (`crates/roym_directory/src/app.rs`) that aggregates listings and credentials. Hosting is performed by Infrastructure Providers or self-hosting providers via `ControllerAgreement` (`crates/identity/src/substrate.rs:48`).
2. **The Ecosystem diagram retains the obsolete concept `Space`.** The diagram node `SynApp[SynApp: Space / Catalog]` (line 238) uses the word `Space`. In the codebase, `Space` does not exist (Overlaps O24; Glossary entries GLS-13 and GLS-14 in Batch R1). The system uses SynApp manifests (`crates/app_orchestration/src/models/manifest.rs`), Roym catalog services (`crates/roym_catalog`), and listing records (`crates/roym_core/src/listing.rs`).
3. **Several Non-Functional Requirements specify tests or metrics that do not exist.** Line 341 specifies a "24-hour bootstrap outage test", but no bootstrap server exists in code (Owner Decision Q-A8; Matrix row 11 `[PRD-FED]` is Pending for M8). Line 343 specifies p95 latency under 1 second for local UI and under 3 seconds for remote operations across "mobile-network profiles", but mobile phone targets are not built (release pipeline builds desktop/server targets only, Overlaps O23) and mobile network performance profiles are not tested. Line 347 specifies "cross-version fixtures" for data portability, but cross-version fixtures are open in `docs/planning/deferred-backlog.md` (`[G5]`) and Matrix row 13 (`[PRD-POR]`).
4. **Core offline and asynchronous guarantees are solidly implemented.** Outbox persistence (`crates/async_queue/`, `crates/conversation/`), idempotency enforcement on retries (ADR-0023 §4), transactional state machines without silent last-write-wins (`crates/roym_core/src/transaction.rs:86`), and end-to-end messaging encryption (`crates/conversation/src/crypto.rs`) are fully verified by automated tests (`crates/substrate/tests/saga_e2e.rs`, `roym_group_offline_e2e.rs`, `roym_restore_e2e.rs`).

## 4. Gaps noticed

1. **Fine-grained Data Access Engine (FDAE) and ReBAC pushdown (`ADR-0017`).** Common Requirements specify owner-approved access policies (line 314) and conflict arbitration (line 305), but omit FDAE: declarative ReBAC compiled into SQLite `WHERE EXISTS` queries with row pruning and column masking, plus stage-4 WASM guest ABAC authorizers (`crates/fdae/`, `crates/data_db/src/sqlite/provider.rs`).
2. **Two-tier identity architecture: Master Keys vs Instance Keys (`ADR-0020`).** NFR Identity Security (line 340) requires that routine key rotation does not change public identities. The code implements this through stable master DIDs (for nodes, app instances, and services) issuing scoped `DelegationCertificate`s (`SCOPE_ROUTING`, `SCOPE_SERVICE_INSTANCE`) to relocatable instance keys (`crates/identity/src/delegation.rs`). This structure is missing from Common Requirements.
3. **Envelope encryption with KEK/DEK hierarchy and `mlock` memory protection (`ADR-0006`).** NFR Security (line 339) specifies encryption at rest by default. The code implements envelope encryption using an `mlock`'d KEK in host memory and per-service encrypted DEKs in `substrate.db` (`crates/data_keystore/src/key_store.rs:29-50`). This concrete cryptographic mechanism is not mentioned in Common Requirements.
4. **Client Gateway HTTP proxy and session token authentication (`ADR-0024`).** The diagram and INF-06 mention browser clients, but omit the Client Gateway on port 7960 that validates cookies and session bearer tokens to bridge web requests into delegated Ed25519 DIDs (`crates/client_gateway/src/gateway.rs:73`, `session.rs`).
5. **Universal Proxy and text route preamble wire protocol (`ADR-0014`).** Connectivity and messaging requirements (lines 294, 313) specify P2P connections and service cards, but omit the text route preamble (`<scheme>://<interface>.<service_id>[?enc=...]`) and Universal Proxy dispatch layer (`crates/router/src/proxy.rs`, `preamble.rs`).
6. **In-process MQTT Broker for asynchronous event pub/sub.** Messaging requirements (lines 316–319) focus on direct conversation messaging, omitting the embedded `rumqttd` broker that handles pub/sub events over WIT `syneroym:messaging` (`crates/mqtt_broker/src/lib.rs`).
7. **Dual-build SynApp execution model (`ADR-0022`).** INF-05 specifies packaging SynApps as WASM modules or OCI images, but omits the dual-build execution model where SynApps compile both as `wasm32-wasip2` components and natively into `syneroym-substrate` with byte-level behavioral parity (`crates/app_host_native/tests/dual_build_parity.rs`).
8. **App Supervisor for resident multi-substrate orchestration (`ADR-0021`).** Diagram edge `SynApp -->|orchestrates| SynSvc` (line 250) mentions orchestration, but omits the App Supervisor: resident reconcile loop, dependency binding injection, and multi-substrate placement (`crates/app_supervisor/src/lib.rs`).
9. **Saga compensations for distributed recovery (`ADR-0023`).** Offline & connectivity requirements (lines 301–307) specify conflict arbitration, but omit the saga compensation engine that executes compensating actions when multi-step offline operations fail midway (`crates/async_queue/src/saga.rs`, tested in `crates/substrate/tests/saga_e2e.rs`).
