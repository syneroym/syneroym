# Audit: architecture material that `system-architecture.md` does not cover

Reader: a developer who will decide what to add to [system-architecture.md](../../../system-architecture.md).

This is a read-only gap audit. I changed no code and no doc. Part of the
[living docs baseline](change.md). All checks are static reading. I did not run
the substrate or the tests.

Paths are from the repository root. "Doc today" gives line numbers in the
architecture doc as it is now (Layer 2 was rewritten recently, so I read the
current text). "Status" says whether the code does it (Implemented), does part of it
(Partial), or the design is not built (Envisioned).

## 3. How I searched

I read the README rules, the two style sections of `AGENTS.md`, and the Layer 2 audit for tone. I listed every crate under `crates/` and `apps/`, the nine fields of `RolesConfig`, all 12 WIT interface folders and all 25 ADRs. For each item I searched the doc by crate name, type name and concept (`grep -i`, count and line numbers). I then read the doc text around the hits. For the cross-cutting topics I read the running code: `runtime.rs`, `services.rs` (failure), `lifecycle.rs` (upgrade, removal), `tls.rs`, `Dockerfile`, and `substrate/Cargo.toml` (topology). I kept only items that meet one of the four tests in the task. I left out crates with no boundary role (`smoke-tests`, `chunk_transfer`, `ucan` and `fdae` internals that the doc already covers through ADR-0015 and ADR-0017). I did not verify the body of ADR-0019 against code, and I did not check what removal does to a service database.
